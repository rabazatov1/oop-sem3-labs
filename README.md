# Лабораторная работа 2: класс с ручным управлением памятью

Класс `Matrix` с плоским динамическим буфером `double*`, RAII, правилом пяти и идиомой copy-and-swap, плюс консольное меню для работы с ним. Вариант 19: `submatrix(r, c)`, копия матрицы без строки `r` и столбца `c`.

---

## О проекте

Лабораторная работа 2 по ООП (МАИ, каф. 806, 01.03.02 «Прикладная математика и информатика»), семейство C: матрица с хранением элементов в одном динамическом массиве `double*` построчно. Элемент `(r, c)` лежит по индексу `r * cols + c`.

Класс сам управляет своей памятью: конструктор выделяет буфер, деструктор освобождает его. Копирование глубокое, перемещение забирает буфер за O(1) и обнуляет источник, присваивание сделано через copy-and-swap. Ошибки по контракту сообщаются исключениями.

Ввод и вывод класс не делает, кроме метода `print`, который пишет в любой `std::ostream`. Меню, чтение чисел и сообщения живут отдельно, в `main.cpp`. Благодаря этому класс вызывается и из программы, и из автоматических тестов.

Алгоритм варианта 19:

- `submatrix(r, c)` возвращает новую матрицу размера `(rows - 1) x (cols - 1)`: все элементы исходной, кроме строки `r` и столбца `c`. Исходная матрица не меняется.

Пример: для матрицы `[[1, 2, 3], [4, 5, 6], [7, 8, 9]]` вызов `submatrix(1, 1)` даёт `[[1, 3], [7, 9]]`.

## Меню программы

```
1. Создать матрицу
2. Задать элемент
3. Напечатать
4. Алгоритм варианта (submatrix)
0. Выход
```

| Пункт | Что происходит |
|---|---|
| 1 | Запрашивает число строк, столбцов и значение, создаёт матрицу и заполняет ею все ячейки. Старая матрица освобождается автоматически |
| 2 | Запрашивает строку, столбец и значение, записывает его в ячейку |
| 3 | Печатает матрицу в виде `[[1, 2], [3, 4]]` |
| 4 | Запрашивает номера удаляемых строки и столбца, печатает результат `submatrix` |
| 0 | Завершает программу, память освобождает деструктор |

Некорректный ввод (буквы, отрицательные числа) не роняет программу: выводится сообщение, и меню показывается снова. Индексы вне матрицы в пунктах 2 и 4 дают сообщение об ошибке из исключения `std::out_of_range`. В начале работы матрица пустая (0x0).

## Класс `Matrix`

Определён в `include/lab2/matrix.hpp`, пространство имён `lab2`.

### Конструкторы, правило пяти

| Член | Назначение |
|---|---|
| `Matrix()` | Пустая матрица 0x0, память не выделяется |
| `Matrix(rows, cols, value = 0.0)` | Матрица `rows x cols`, все элементы равны `value` |
| `Matrix(const Matrix&)` | Глубокое копирование буфера |
| `Matrix(Matrix&&) noexcept` | Забирает буфер за O(1), источник становится 0x0 |
| `operator=(Matrix) noexcept` | Присваивание через copy-and-swap, одно для копирования и перемещения |
| `~Matrix()` | `delete[]` буфера |
| `swap(Matrix&) noexcept` | Обмен размерами и указателями |

### Методы

| Метод | Назначение |
|---|---|
| `rows()`, `cols()` | Размеры матрицы |
| `get(r, c)` | Читает элемент, при выходе за границы бросает `std::out_of_range` |
| `set(r, c, value)` | Записывает элемент, при выходе за границы бросает `std::out_of_range` |
| `add(other)` | Прибавляет `other` поэлементно, при разных размерах бросает `std::invalid_argument` |
| `mul(other)` | Заменяет матрицу произведением `this * other`, при `cols() != other.rows()` бросает `std::invalid_argument` |
| `submatrix(r, c)` | Алгоритм варианта: копия без строки `r` и столбца `c`, при выходе за границы бросает `std::out_of_range` |
| `print(os)` | Печатает матрицу в поток, для пустой матрицы выводит `[]` |

Свободные функции: `operator==`, `operator<<` и `swap(a, b)`.

Контракты:

- Инвариант: `data_ == nullptr` тогда и только тогда, когда в матрице нет элементов; иначе `data_` указывает на массив из `rows_ * cols_` элементов.
- `add` и `mul` возвращают `Matrix&`, поэтому вызовы можно объединять в цепочку.
- `mul` строит результат во временной матрице и подменяет его через `swap`, поэтому `m.mul(m)` работает, а при ошибке исходная матрица не меняется.
- `submatrix` для матрицы 1x1 возвращает пустую матрицу 0x0.

## Тесты

26 тестов в двух наборах:

- `MatrixTest` (22): конструкторы, глубокое копирование, перемещение, копирующее и перемещающее присваивание, самоприсваивание, `add`, `mul` (квадратные, прямоугольные и `m.mul(m)`), `print`, семь тестов `submatrix` (середина, первая и последняя строка и столбец, неквадратная матрица, независимость результата, матрица 1x1);
- `MatrixTest_Throw` (4): ожидаемые исключения, то есть выход за границы в `get`, `set` и `submatrix`, несовпадение размеров в `add` и `mul`.

Ожидаемые значения заданы константами, а не вычисляются теми же методами.

## Проверка памяти

Сборка идёт с `-fsanitize=address`: он находит выходы за границы, обращение после освобождения и двойной `delete[]`. На macOS проверка утечек в ASan недоступна, а сборка с ним может не запускаться, поэтому там утечки проверяют отдельно:

```bash
MallocStackLogging=1 leaks --atExit -- ./build/tests
```

Основная проверка перед сдачей: сборка и запуск тестов на Linux с GCC.

### Ограничения лабораторной

Запрещены `std::string`, `std::vector`, `std::array` и умные указатели. Память выделяется только вручную через `new[]` и освобождается через `delete[]`, управление ею делает сам класс.
